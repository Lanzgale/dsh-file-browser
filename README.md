# dsh-file-browser

> **File Browser for DeepSeek Harness** — right-side resizable file tree with Markdown rendering and syntax highlighting. Install: `dsh plugin --profile web add dsh-file-browser`.

DeepSeek Harness 的全局文件浏览器插件：在**右侧边栏**里画一棵文件树，单击文本文件即时预览、可直接编辑。侧边栏本身（列的开合、标题行、右上角按钮、深浅配色）由接口插件 `dsh-rightbar-shell` 提供；本插件只负责树和预览这两块内容。

> **上游**：本插件 fork 自 [joejojoking-cloud/dsh-file-explorer](https://github.com/joejojoking-cloud/dsh-file-explorer)（MIT License），已更名并深度定制（双主题、刷新保持展开、隐藏文件开关、内嵌预览等）。原始版权归上游作者所有。

## 功能

- 右侧面板：本插件向外壳 `dsh-rightbar-shell` 登记一个**档位**（`ctx.rightbarShell.addMode`，自报 `order: 1`，所以在外壳的档位菜单里排在仓库浏览器（2）上面、也是默认档位），内容就画在那一列里；**开合**走会话标题栏右上角的入口按钮（它只在面板收起时渲染），面板打开后由外壳标题行的收起按钮关闭
- 标题行由接口插件绘制：左边是「图标 + 当前浏览器名」的切换按钮，右端依次是 深浅切换 / **显示隐藏文件** / **刷新** / 收起侧边栏（中间两个由本插件提供）；**打开文档时外壳整行让位**，改由文档自己的标题行（文件名 + 四个按钮）接管，永远只有一行
- 文件树：根目录默认展开，目录点击展开/折叠（懒加载），单击文本文件立即内嵌预览、**再点一次同一个文件收起预览**（中间那 220ms 里来的双击会取消收起，所以双击不会闪），单击非文本仅选中
- 排列：**文件夹在上、文件在下**，两组各自按名称升序；名称分两档——数字/英文按 A→Z（数字按数值比，`2` 在 `10` 前），中文名整档排在后面、档内按拼音
- **折叠以下全部**：目录行右端有一个 `chevron-double-up` 按钮，只在该层底下确实还有展开的目录时才出现；点它把那层以下的子孙目录一次性收起（本级保持展开）
- 图标一律取自 Material Design Icons（mdi）的 24×24 路径，随主题文字色自动适配
- 预览：`.md` 渲染 Markdown（标题/列表/代码块/引用/链接），代码按扩展名自动语法高亮；文档标题行右端四个按钮，从左到右是 **编辑 / 保存**、**全屏 / 退出全屏**、**重新读取文件**、**返回**（字号缩放按钮已移除，预览用固定字号：正文 13px、源码 12px、标题 20/17/15/13px）
- **从对话里的文件卡片直接进预览**：不管侧边栏此刻停在哪个档位（例如仓库浏览器），点卡片都会自动切回文件浏览器并载入该文件。请求走的是一个**信箱**（`store.pendingOpen`）：面板没挂载时也能收下，**取走即清空**——消息取走就没了，所以面板重挂载不会把上一条请求当成新的重放一遍（早先那个「每次打开侧边栏都进上次那个文件」的 bug 就是这么来的）
- **返回即定位**：返回 = 回文件树 + 露出这个文件——展开它上面的每一级目录，并把**装着它的那个目录**那一行滚到面板最上端；**目标行已经看得见就不滚动**（文件树在预览期间只是被藏起来、没有卸载，所以滚动位置留得住）。上级里有名字以 `.` 开头的目录时会顺带打开「显示隐藏文件」。**路径一律按绝对路径处理**——对话文件卡片转来的是相对会话工作目录的写法，由外壳先还原（见 `dsh-rightbar-shell/README.md` 的事件协议）
- **全屏**：预览工具栏的全屏按钮让这一列铺满整个窗口（再点一次退出，图标在 `Fullscreen` ⟷ `FullscreenExit` 之间切）；铺满的样式由外壳画，收起侧边栏也会一并退出全屏
- 超过 1 MB 的文件提示不支持预览
- 专注浏览：**搜索功能已移除**（查找文件请交给 agent 或命令行）；目录列表与展开状态**持久化**，关网页/刷新/重启后秒回原样
- **新会话页自动隐藏**：未选会话、或当前是空白会话（新建未发言）时不渲染面板，并同时撤掉给内容让位的布局边距；`open` 开关本身不改动，回到真实会话原样恢复

## 编辑与未保存的改动

- **入口就是标题行最左那一个按钮**：只读时画铅笔（`pencil-outline`；`.md` 上悬停提示是「编辑源码」），点它进编辑态；编辑态同一格变成对勾（`check-outline`）。**颜色即状态**——编辑态**有改动就是蓝的**（等着你保存），**没改动是默认灰**（点了只是退出编辑），冲突时变实心警示色（这一下是覆盖磁盘）。右侧三格（全屏 / 重新读取 / 返回）的位置永远不动
- **编辑只有一种形态**：纯文本 textarea。`.md` 也一样——进编辑就是源码界面，只读态永远是渲染结果，所以**不再有「预览 / 源码」切换按钮**（看源码 = 进编辑态，不想改就直接返回，不落盘）
- **保存是显式动作**：点保存才写盘。没有自动保存，也**不绑任何快捷键**（Ctrl+S 会撞上浏览器自带的「保存网页」；同一个动作两条入口本身就是第二套路径）。**没有改动时点保存只是退出编辑，不写盘**
- **能读才能改**：只有读得出来的文本文件才出现编辑按钮（超过 1 MB、二进制、读失败的文件没有）
- **有未保存改动时，出口都要点两次**：重新读取 / 返回 / 对话卡片换文件，第一次点击只进入「武装态」——那个按钮变实心警示色、标题行出现一句灰色「修改未保存」，3 秒内再点一次才真的执行（= 明确丢弃）；**你又开始打字就自动解除武装**。没有改动时全部一次点击生效
  - 文档态**只有「返回」一个出口**：会话标题栏那个入口按钮只在面板收起时渲染，面板内的收起按钮长在外壳标题行上、文档态整行让位。所以文档里想出去就得先返回
- **保存冲突由文件服务拦下**：读文件时带回内容版本号（`设备:inode:大小:mtime:ctime`），保存时原样交回；文件在你编辑期间被改过（例如模型刚写过）就会被拒（409）。这时标题行显示灰色「磁盘已变」，保存按钮变成实心警示色 = **覆盖磁盘**；想放弃自己的改动就点「重新读取」。不做自动合并——猜错比拒绝更糟
- **视图快照**：面板的样子（在文件树 / 打开着哪个文件 / 是否在编辑 / 未保存的正文 / 两处滚动比例）写在 localStorage，**只存当前这一份**。刷新、关标签、关浏览器、DSH 重启、插件热重载之后重开侧边栏，回到离开前的样子（含没保存的正文与滚动位置）。不按文件存多份草稿，所以不会攒出一堆未保存的编辑；快照里的文件已经读不出来（被删/改名）就退回文件树并清掉它
- 滚动位置按**内容高度的比例**记、按同一比例还原：只读态和编辑态的排版不同（尤其 `.md`：渲染结果 vs 原文），逐像素搬没有意义

## 缓存与刷新

- 目录列表缓存 + **展开状态**持久化在浏览器 localStorage（按工作区根目录）：关网页、Ctrl+Shift+R、重启 DSH 后重开面板，**原样恢复**（含展开的目录）
- **面板的样子**（在树里还是在某个文件里、是否在编辑、未保存的正文、滚动比例）也写 localStorage，同一套约定、只存一份；详见「编辑与未保存的改动」
- 树**不是实时扫描**：目录首次展开时扫描并缓存；收起再展开、面板重开都用缓存（秒回）
- 刷新按钮**只重新扫描已展开的目录**，未展开目录沿用缓存
- **AI 改文件会自动刷新**：host 把「哪些目录变了」推给面板（实时流），面板只重扫受影响的已展开目录；当前预览的文件若正好在那个目录里也会重读，但**正在编辑时不重读**（免得冲掉没保存的改动）
- 面板**之外**改的文件（终端里手动改、用别的编辑器改）不会推——那类还是点**刷新按钮**
- 排序在「数据进入缓存」时做一次（拉取、读本地缓存两个入口都排），所以浏览器里存的旧缓存重开时也会当场重排，不必清缓存
- 缓存仅在两种情况下丢失：清除该站点的浏览器数据、隐私/无痕模式关窗

## 预览支持的文件类型

单击文本文件立即内嵌预览（代码按扩展名自动语法高亮）：

| 类别 | 扩展名 |
|---|---|
| Markdown | `.md` `.markdown` `.mdown` `.mkd` —— 渲染标题/列表/代码块/引用/链接；看源码请进编辑态（只读态永远是渲染结果） |
| 纯文本 | `.txt` |
| 脚本 / 代码 | `.py` `.pyw`、`.js` `.mjs` `.cjs` `.jsx`、`.ts` `.mts` `.cts` `.tsx`、`.c` `.h`、`.cpp` `.cc` `.cxx` `.hpp` `.hh` `.hxx`、`.java`、`.go`、`.rs`、`.sh` `.bash` `.zsh` |
| 数据 / 配置 | `.json` `.jsonc` `.map`、`.yaml` `.yml`、`.toml`、`.ini` `.cfg` `.conf`、`.sql` |
| 标记 / 样式 | `.html` `.htm`、`.css` `.scss` `.less` |

**不能预览**：

- **非文本 / 二进制文件**（图片、PDF、音视频、压缩包、可执行文件等）——单击仅选中，不读取内容
- **超过 1 MB 的文本文件**——提示「文件过大，不支持预览」

## 安装

```sh
dsh plugin --profile web add <本包路径或 npm 包名>
```

重启 harness 后生效：所有会话都会加载该插件（host 路由 `/plugins/file-browser/*` + web client 面板）。

## 结构

- `lib/index.js` — host 半部：`fs`/`shell` 服务 + `webServer` HTTP 路由（`list` / `read`（带回内容版本号）/ `write`（**乐观锁**——读的时候记下这一版内容的"指纹"，写的时候把指纹交回来，对不上就拒收，也就是"不锁文件、撞上才拒绝"：必须带版本号，过期回 409 `stale`，`force` 才允许覆盖，>1 MB 拒绝）/ `open-vscode` / **`events`**——SSE 变更流，供「AI 改文件自动刷新」用）
- `lib/client.js` — web client 半部：`window.__ModuleLoader__` bundle，向外壳登记 `rightbar` 档位（内容 + 工具按钮），并镜像外壳的全屏状态
- `cordis.patch.yml` — bundle 补丁，把 `file-browser` 行插入 profile 的 host 组合

## 已知缺口

写在这里是为了别把"没做"记成"做了"：

- **行号定位：明确不做**（定论，不是待办）。外壳会把 `line` 一并转过来（`dsh:sidebar-right:open` 载荷里有），预览只接收、不使用。理由是它**没法只有一个判据**：一旦要定位，落地行为就得按文件类型和大小分叉——`.md` 得先切到源码视图（渲染预览里行号没有对应物），超过 1 MB 的文件连内容都读不出来；同一件事几种落地方式，正是这个项目一直在消掉的那种不一致。收益也已被覆盖：read 工具卡片展开就列着读到的那几行。
- **「能不能看」有两个答案**：从文件树点开的判据是「扩展名在不在上色表里」，所以 `Makefile`、`.csv`、`.log` 这类**纯文本**点不开（只选中）；而从对话卡片打开是什么文件都读。同一个问题两处判据，建议以后统一成「能不能读出文本」（超出大小 / 二进制交给文件服务拒绝）。
- **PDF 不能预览**：非文本文件一律只选中、不读取。
